Ein eigener Server für deine Trainingsgruppe

Mit einem eigenen Server trackt deine Freundesgruppe Workouts gemeinsam: Arena mit Jahres-Saison und Monatssiegern, Könige, Kämpfe, Challenges und personalisierte Kämpfer. Der Server läuft bei euch – am einfachsten auf einem Raspberry Pi daheim. Kostenlos, und eure Daten gehören euch.

So funktioniert es

App von GitHubAlle nutzen dieselbe App: maxrci.github.io/gymapp. Sie läuft auf iPhone und Android und funktioniert auch offline.
Server bei euchEuer Server speichert nur die Daten der Gruppe – eine kleine SQLite-Datei, wenige MB. Gruppen sehen sich gegenseitig nicht.
Du legst die Konten anNiemand kann sich selbst registrieren. Du vergibst Benutzername und Passwort, jedes Gerät meldet sich einmal an und bleibt angemeldet.

Die App bleibt offline-fähig: Workouts werden zuerst auf dem Handy gespeichert und im Hintergrund mit dem Server abgeglichen. Fällt der Server mal aus, trainiert jeder normal weiter.

Was du brauchst

  • Einen Raspberry Pi 3, 4 oder 5 (oder einen anderen Linux-Rechner) mit Ubuntu 24.04 oder Raspberry Pi OS (64 Bit), per SSH erreichbar.
  • Internet am Pi. Eine Domain oder Portfreigabe im Router brauchst du mit Variante A nicht.
  • 10 Minuten Zeit.

Installation

  1. Server installieren

    Per SSH auf den Pi und Folgendes ausführen. Das Skript installiert Node.js 24, legt die Einstellungen in /etc/gym.env an und richtet den Dienst gym ein, der automatisch beim Booten startet.

    sudo apt update && sudo apt install -y git
git clone https://github.com/maxrci/gymapp.git ~/gym
cd ~/gym
bash deploy/pi-setup.sh

    Danach läuft der Server lokal auf dem Pi (Port 8080). Prüfen mit curl http://127.0.0.1:8080/api/info.

  2. Online erreichbar machen (HTTPS)

    Die App läuft über HTTPS, deshalb braucht auch dein Server eine HTTPS-Adresse. Wähle eine Variante:

    Empfohlen · kostenlos · ohne Router-Einstellungen

    A · Tailscale Funnel

    Tailscale gibt deinem Pi eine feste öffentliche Adresse wie https://pi.tail1234.ts.net – ohne Domain, ohne Portfreigabe, funktioniert auch hinter DS-Lite/Kabelanschlüssen. Deine Freunde brauchen kein Tailscale.

    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up                 # Link öffnen, mit Google/GitHub/Apple anmelden
sudo tailscale funnel --bg 8080   # beim ersten Mal: angezeigten Link öffnen und Funnel erlauben
tailscale funnel status           # zeigt deine https://…ts.net-Adresse

    Die Adresse dann als PUBLIC_URL eintragen:

    sudo nano /etc/gym.env            # PUBLIC_URL=https://pi.tail1234.ts.net
sudo systemctl restart gym

    Der kostenlose Personal-Plan von Tailscale ist für private, nicht-kommerzielle Nutzung gedacht – für eine Freundesgruppe passt das.

    Mit Portfreigabe

    B · DuckDNS + Caddy

    Kostenlose Adresse wie gym-crew.duckdns.org. Voraussetzung: dein Internetanschluss hat eine öffentliche IPv4-Adresse (kein DS-Lite) und du kannst im Router die Ports 80 und 443 zum Pi weiterleiten.

    # 1. Auf duckdns.org anmelden, Subdomain anlegen, Token kopieren
# 2. IP alle 5 Minuten aktualisieren:
(crontab -l 2>/dev/null; echo "*/5 * * * * curl -s 'https://www.duckdns.org/update?domains=gym-crew&token=DEIN-TOKEN&ip=' >/dev/null") | crontab -
# 3. Caddy holt automatisch ein HTTPS-Zertifikat:
sudo apt install -y caddy
echo 'gym-crew.duckdns.org {
  reverse_proxy 127.0.0.1:8080
}' | sudo tee /etc/caddy/Caddyfile
sudo systemctl restart caddy
# 4. Im Router: Ports 80 und 443 → Pi
# 5. sudo nano /etc/gym.env → PUBLIC_URL=https://gym-crew.duckdns.org ; sudo systemctl restart gym
    Mit eigener Domain

    C · Cloudflare Tunnel

    Wenn du eine eigene Domain bei Cloudflare hast: im Cloudflare-Dashboard unter Zero Trust → Networks → Tunnels einen Tunnel anlegen, die angezeigten Installationsbefehle für „Debian / arm64“ auf dem Pi ausführen und als Ziel http://localhost:8080 eintragen. Danach PUBLIC_URL setzen wie oben.

  3. Dich als Admin anlegen

    cd ~/gym
bash deploy/cli.sh admin "Max" max                 # Passwort wird zufällig erzeugt
bash deploy/cli.sh admin "Max" max MeinPasswort1   # oder selbst festlegen

    Ausgegeben werden Benutzername, Passwort und ein Anmelde-Link. Öffne den Link auf deinem Handy – oder öffne die App und gehe zu Profil → Gruppe → Bei Gruppe anmelden und gib Server-Adresse, Benutzername und Passwort ein.

  4. Freunde anlegen

    In der App unter Profil → Gruppe verwalten → Nutzer anlegen: Name, Benutzername und Passwort eintragen (leer lassen = zufälliges Passwort wie kraft-tiger-4827). Danach erscheint eine Karte mit den Zugangsdaten und dem Button „Zugangsdaten verschicken“ – z. B. per WhatsApp.

    Oder auf dem Pi: bash deploy/cli.sh add "Lisa" lisa. Passwort vergessen? In der App „Passwort neu setzen“ oder bash deploy/cli.sh passwd lisa.

  5. So melden sich Freunde an

    iPhone: Link in Safari öffnen → Teilen → „Zum Home-Bildschirm“. Dann die App vom Home-Bildschirm öffnen und unter Profil → Gruppe → Bei Gruppe anmelden die Server-Adresse (oder den ganzen Einladungstext) einfügen, Benutzername und Passwort eingeben. Wichtig: in der installierten App anmelden – sie hat einen eigenen Speicher.

    Android: Link in Chrome öffnen, anmelden, dann im Menü „App installieren“.

    Jedes Gerät meldet sich nur einmal an und bleibt angemeldet. Vorhandene Workouts auf dem Handy werden dabei automatisch hochgeladen.

Sichtbarkeit & Datenschutz

Jeder entscheidet selbst unter Profil → Sichtbarkeit, was die anderen sehen:

StufeDie anderen sehen
1 · Nur ZahlenArena-Punkte, Bestwerte, Streak, Challenges – keine Workouts
2 · ÜbersichtZusätzlich Workouts mit Titel, Datum, Dauer, Volumen, Übungen
3 · KomplettWorkouts mit allen Sätzen, Gewichten und Wiederholungen

Passwörter werden nur als scrypt-Hash gespeichert, Anmelde-Tokens als SHA-256-Hash. Nach 10 falschen Passwörtern pro Benutzername ist für 15 Minuten Pause.

Backups

bash deploy/cli.sh backup ~/gym-backup-$(date +%F).db
# Täglich um 4 Uhr automatisch:
(crontab -l 2>/dev/null; echo "0 4 * * * cd ~/gym && bash deploy/cli.sh backup ~/backups/gym-\$(date +\%F).db") | crontab -
mkdir -p ~/backups

Wiederherstellen: Dienst stoppen (sudo systemctl stop gym), Sicherung nach ~/gym/data/gymlog.db kopieren, Dienst starten.

Updates

cd ~/gym && git pull && sudo systemctl restart gym

Die App selbst aktualisiert sich über GitHub automatisch beim nächsten Öffnen.

Mit Docker (statt Skript)

Docker-Variante anzeigen 
curl -fsSL https://get.docker.com | sh
git clone https://github.com/maxrci/gymapp.git ~/gym && cd ~/gym
cp .env.example .env && nano .env
docker compose up -d --build                    # nur lokal (Port 8080, z. B. mit Tailscale Funnel)
docker compose --profile caddy up -d --build    # mit Caddy (Variante B)
docker compose --profile tunnel up -d --build   # mit Cloudflare Tunnel (Variante C)
docker compose exec gymlog node server/cli.js admin "Max" max

Fehlerbehebung

ProblemLösung
„Server nicht erreichbar“ in der AppAdresse mit https:// eingeben. Auf dem Handy im Browser https://deine-adresse/api/info öffnen – dort muss {"app":"gymlog",…} stehen.
Dienst läuft nichtsystemctl status gym und journalctl -u gym -n 50
„Benutzername oder Passwort falsch“Benutzername ist klein geschrieben (z. B. lisa.mueller). Neues Passwort: bash deploy/cli.sh passwd lisa.mueller
„Zu viele Fehlversuche“15 Minuten warten oder Dienst neu starten.
Funnel-Adresse geht nichttailscale funnel status prüfen; im Tailscale-Admin unter DNS „HTTPS Certificates“ aktivieren.
Node-Version zu altnode -v muss ≥ 22.13 sein – bash deploy/pi-setup.sh erneut ausführen.
Gym · Open Source · Fragen und Wünsche: in der App unter Profil → „Wünsche & Fehler melden“.
