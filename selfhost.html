GymLog · Selbst hosten

Ein eigener Server für deine Trainingsgruppe

Mit dem GymLog-Server trackt deine Freundesgruppe Workouts gemeinsam: mit Liga, Ewiger Tabelle, Challenges und personalisierten Kämpfern. Der Server läuft bei euch – auf einem Raspberry Pi daheim oder einem günstigen Cloud-Server. Eure Daten gehören euch.

So funktioniert es Was du brauchst 1. Docker installieren 2. GymLog herunterladen 3. Online stellen (HTTPS) 4. Ersten Admin anlegen 5. Freunde einladen Sichtbarkeit & Datenschutz Backups Updates Ohne Docker Fehlerbehebung

So funktioniert es

Ein Server pro GruppeJede Freundesgruppe betreibt ihren eigenen Server. Gruppen sehen sich gegenseitig nicht.
Keine PasswörterDer Admin legt Mitglieder an und verschickt jedem einen persönlichen Einmal-Schlüssel. Eine offene Registrierung gibt es nicht.
Offline zuerstDie App speichert alles auf dem Handy und gleicht sich im Hintergrund mit dem Server ab. Im Gym ohne Netz geht nichts verloren.
App kommt vom ServerIhr öffnet eure eigene Adresse (z. B. gym.example.de) und installiert die App von dort auf dem Home-Bildschirm.

Warum HTTPS Pflicht ist: Nur über eine verschlüsselte Verbindung lässt sich die App auf iPhone und Android installieren und offline nutzen. Alle drei Varianten unten richten HTTPS automatisch ein – du musst dich um keine Zertifikate kümmern.

Installation

  1. Docker installieren

    Per SSH auf dem Pi bzw. Server anmelden und Folgendes ausführen:

    curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# einmal ab- und wieder anmelden, damit die Gruppe greift

  2. GymLog herunterladen und einstellen

    git clone -b distribution https://github.com/maxrci/gymapp.git
cd gymapp
cp .env.example .env
nano .env

    In der .env trägst du ein:

    • GROUP_NAME – Name eurer Gruppe, z. B. Gym-Crew
    • PUBLIC_URL – die spätere Adresse mit https://, z. B. https://gym.example.de (für Einladungslinks)
    • je nach Variante DOMAIN oder TUNNEL_TOKEN (siehe nächster Schritt)

  3. Online stellen – eine Variante wählen

    Empfohlen für daheim

    A · Raspberry Pi mit Cloudflare Tunnel

    Kein Port im Router nötig, die IP-Adresse deines Anschlusses bleibt verborgen, HTTPS ist automatisch dabei. Du brauchst eine eigene Domain, die bei Cloudflare verwaltet wird (kostenloses Konto).

    1. Domain bei Cloudflare hinzufügen (oder dort kaufen).
    2. Im Cloudflare-Dashboard: Zero Trust → Networks → Tunnels → Create a tunnel → Typ Cloudflared → Umgebung Docker. Den angezeigten Token kopieren (die lange Zeichenkette nach --token).
    3. Unter Public Hostname eintragen: Subdomain gym, deine Domain, Service HTTP und URL gymlog:8080.
    4. In der .env: TUNNEL_TOKEN=… und PUBLIC_URL=https://gym.deine-domain.de
    5. Starten:
    docker compose --profile tunnel up -d --build
    Kostenlos, ohne Domain

    B · Raspberry Pi mit DynDNS und Portfreigabe

    Für eine kostenlose Adresse wie deine-gruppe.duckdns.org. Dafür gibst du im Router zwei Ports frei; Caddy holt das HTTPS-Zertifikat automatisch.

    1. Bei einem kostenlosen DynDNS-Dienst (z. B. DuckDNS) eine Subdomain anlegen und das Update-Skript bzw. den Cronjob auf dem Pi einrichten, damit die Adresse immer auf deinen Anschluss zeigt. Viele Router (z. B. FRITZ!Box: Internet → Freigaben → DynDNS) können das auch selbst.
    2. Im Router dem Pi eine feste IP geben und die Ports 80 und 443 (TCP) an den Pi weiterleiten.
    3. In der .env: DOMAIN=deine-gruppe.duckdns.org und PUBLIC_URL=https://deine-gruppe.duckdns.org
    4. Starten:
    docker compose --profile caddy up -d --build

    Hinweis: Manche Anschlüsse (DS-Lite, Glasfaser ohne eigene IPv4) erlauben keine Portfreigaben. Dann nimm Variante A.

    Ohne Hardware daheim

    C · Cloud-Server

    1. Einen kleinen Linux-Server (Ubuntu oder Debian) mieten.
    2. Bei deinem Domain-Anbieter einen A-Eintrag setzen, z. B. gym.example.de → IP-Adresse des Servers.
    3. In der Firewall des Anbieters die Ports 80 und 443 öffnen.
    4. Schritte 1 und 2 oben ausführen, in der .env DOMAIN und PUBLIC_URL setzen und starten:
    docker compose --profile caddy up -d --build

    Danach sollte https://deine-adresse die App zeigen. Kontrolle: docker compose logs -f gymlog

  4. Ersten Admin anlegen

    docker compose exec gymlog node server/cli.js admin "Dein Name"

    Die Ausgabe zeigt einen Schlüssel wie K7QF-2MXA-9TPD-H4WN und einen Link. Öffne den Link auf deinem Handy – fertig, du bist Admin. Der Schlüssel funktioniert einmal und ist 7 Tage gültig.

  5. Freunde einladen

    In der App: Profil → Gruppe verwalten → Nutzer anlegen. Du bekommst für jede Person einen persönlichen Schlüssel samt Link, den du per Messenger verschickst. Für jedes weitere Gerät (z. B. iPad) erstellst du einen neuen Schlüssel.

    iPhoneLink in Safari öffnen → Teilen → „Zum Home-Bildschirm“ → App öffnen → Profil → Gruppe → Mit Schlüssel anmelden. (Die installierte App hat einen eigenen Speicher, deshalb erst installieren, dann anmelden.)
    AndroidLink in Chrome öffnen, anmelden und über ⋮ → App installieren auf den Startbildschirm legen.

    Wer schon Workouts lokal in GymLog hat (oder eine CSV importiert), dessen Verlauf wird beim Anmelden automatisch hochgeladen und zählt für die Ewige Tabelle.

Sichtbarkeit & Datenschutz

Jedes Mitglied entscheidet unter Profil → Gruppe → Sichtbarkeit selbst, was die anderen sehen:

StufeDie anderen sehen
1 · Nur ZahlenLiga-Punkte, Bestwerte in der Ewigen Tabelle, Streak, Kämpfer und Challenge-Stände – aber keine Workouts.
2 · ÜbersichtZusätzlich die Workouts mit Titel, Datum, Dauer, Volumen, Übungen und Rekorden.
3 · KomplettWorkouts vollständig mit allen Sätzen, Gewichten und Wiederholungen.

Der Server speichert Schlüssel und Geräte-Kennungen nur verschlüsselt (als Hash). Falsche Schlüssel werden nach 10 Versuchen für 15 Minuten gesperrt. Als Admin kannst du einzelne Geräte abmelden, Mitglieder sperren oder löschen. Wer den Server betreibt, hat technisch Zugriff auf alle Daten der Gruppe – hostet also bei jemandem, dem ihr vertraut.

Backups

Alle Daten liegen in einer einzigen Datei unter data/gymlog.db. Sicherung im laufenden Betrieb:

docker compose exec gymlog node server/cli.js backup /data/backup-$(date +%F).db

Automatisch jede Nacht um 3 Uhr (mit crontab -e eintragen, Pfad anpassen):

0 3 * * * cd /home/pi/gymapp && docker compose exec -T gymlog node server/cli.js backup /data/backup-$(date +\%a).db

Das hält sieben Sicherungen (eine pro Wochentag) im Ordner data/. Kopiere sie ab und zu auf einen anderen Rechner oder USB-Stick. Wiederherstellen: Server stoppen (docker compose down), Sicherung als data/gymlog.db ablegen, wieder starten.

Updates

cd gymapp
git pull
docker compose --profile tunnel up -d --build   # bzw. --profile caddy

Die Apps auf den Handys aktualisieren sich beim nächsten Öffnen automatisch.

Ohne Docker

Der Server braucht nur Node.js ab Version 22.13 (empfohlen 24) – keine weiteren Pakete. Für HTTPS setzt du dann einen eigenen Reverse-Proxy (z. B. Caddy) davor.

GROUP_NAME="Gym-Crew" PUBLIC_URL="https://gym.example.de" PORT=8080 DATA_DIR=./data \
  node --no-warnings server/server.js

Als Dienst mit systemd (/etc/systemd/system/gymlog.service):

[Unit]
Description=GymLog
After=network.target

[Service]
WorkingDirectory=/home/pi/gymapp
Environment=GROUP_NAME=Gym-Crew PUBLIC_URL=https://gym.example.de PORT=8080 DATA_DIR=/home/pi/gymapp/data
ExecStart=/usr/bin/node --no-warnings server/server.js
Restart=always
User=pi

[Install]
WantedBy=multi-user.target

Verwaltung dann mit node server/cli.js … statt docker compose exec gymlog node server/cli.js ….

Fehlerbehebung

ProblemLösung
„Schlüssel ungültig“Jeder Schlüssel funktioniert nur einmal und 7 Tage lang. Als Admin unter Gruppe verwalten einen neuen erstellen.
iPhone: nach Installation nicht angemeldetDie Home-Bildschirm-App hat einen eigenen Speicher. In der App unter Profil → Gruppe mit einem neuen Schlüssel anmelden.
Seite nicht erreichbardocker compose ps und docker compose logs -f prüfen. Bei Variante B: Portfreigabe und DynDNS kontrollieren.
Kein HTTPS-Zertifikat (B/C)Zeigt die Domain wirklich auf die richtige IP? Sind Port 80 und 443 offen? Caddy-Log: docker compose logs caddy
Liste der Nutzer anzeigendocker compose exec gymlog node server/cli.js users
Admin hat alle Geräte verlorendocker compose exec gymlog node server/cli.js key "Name" erzeugt einen neuen Schlüssel.
